# The gate: what a system would have to be able to say

## The corpus is already an architecture

Four parts, all of them mechanical:

| part | what it does | where it lives |
|---|---|---|
| generator | produces a claim in the corpus's voice | the model |
| zone classifier | places each claim in exactly one of four zones | `the-fold-*.md`, `fold_lint.py` |
| gate | refuses the text if the zones, tables, links or counts disagree | `check.py` |
| void map | records the words with no exact object | the "what does not fold in" tables |

The usual architecture for a learning system is generator plus loss. This one is generator plus a
**verifier** plus a **negative space**, and the third part is the one no benchmark measures. The corpus
is a working instance of it in one narrow domain, with `43` notes, `188` labelled claims and a gate that
has never been bypassed.

## The criterion

An AGI claim needs a test, and "human-level" is not one. The corpus supplies a test that is cheap,
domain-general, and falsifiable:

> **Premise closure.** For every claim the system makes, it emits a zone in
> `{exact, reformulation, rhyme, false friend}` and, if the zone is not `exact`, the **premise** that
> would move it to `exact`. It passes when the premise it names is correct, actionable, and either
> supplied or explicitly marked absent.

Three consequences, each checkable:

1. **Presenting a rhyme as a proof is not a result, it is a failure**, whatever the benchmark says. That is the failure mode
   of every current model, and it is invisible to accuracy metrics because the prose is fluent.
2. **Understanding is closure, not coverage.** A system that says "I do not have the operator for this
   theorem" understands the theorem better than one that states its conclusion in the right style.
3. **The test is a dialogue.** Give the system a claim from `the-fold-problems.md`, and score
   `(zone, premise, smallest host)`. A referee can mark it in seconds. That is an eval that does not
   saturate by training on the eval, because the claim set is generated by the corpus and the corpus is
   open-ended.

Written as a slogan: **an AGI is a system that never confuses a rhyme for a proof, and can always name
the missing premise.** Everything else — scale, multimodality, tool use — is orthogonal to it.

## The type error

Current systems carry a scalar confidence per claim. The corpus carries a **four-valued type**:

```
exact | reformulation | rhyme | false friend
```

These are not degrees of belief. They say *which object the claim denotes*: the same word can be exact
in one register and a false friend in another (`height` is the standing example), and no amount of
probability fixes that, because the values are different *kinds*, not different amounts. Calibration is
the projection of this structure onto a scalar, and the projection loses exactly the information the
gate needs.

This is the one architectural claim in this note that is not speculative: the zone is a type, and a
scalar cannot encode a type.

## The stages

Each stage has a deliverable that the existing gate can check.

| stage | what is added | deliverable | state |
|---|---|---|---|
| 0 | the gate, the zones, the corpus | `check.py`, `fold_lint.py` | done |
| 1 | the theorem ledger | `the-fold-theorems.md`: premises → Fold objects → missing premise → zone, for twelve theorems | done |
| 2 | the void map | `the-fold-void.md`: ten words with no exact object, the nearest object, and the six hosts | done |
| 3 | the host builder | for one missing premise, the smallest exact model, and a distance measure | not started |
| 4 | the adjunction loop | adjoin measure, flow, bath, observer in that order; record which invariants survive | not started |
| 5 | measurement | one gate check tied to an instrument, with units and error bars | not started |
| 6 | self-application | the system zones its own output, including this note | partial |
| 7 | concept formation | task-relative equivalence, abstraction maps, invariants, residual information, counterexample-driven revision | [AGI abstraction and concept formation](agi/abstraction-and-concepts.md) |

Stage 1 is the load-bearing one. A ledger of twelve theorems is small enough to finish and large enough
to show whether "premise closure" is a real capability or a phrase. It is now written, and the answer is
`6 exact / 3 reformulation / 3 rhyme`: the capability is real at the boundary, and it stops at the bulk.

## The four adjunctions

The Fold has no measure, no flow, no bath, no observer. Each is a host, and each has one job:

| adjunction | what it adds | what survives | what dies |
|---|---|---|---|
| a measure | `z(1 − z)` becomes a probability | the quotient | the exactness of the height |
| a flow | `σ` stops being idempotent | the involution as a time-reversal | the static crease |
| a bath | `μ = τ/p*` becomes a fluctuation–dissipation ratio | the ratio | the determinism |
| an observer | the cut becomes a conditioning event | the section | the canonical chart |

The rule from the earlier programme holds: **adjoin one premise at a time and see which invariants
survive.** The survivors are the exact core of the physical theorem; the casualties are the borrowed
physics. That is concept formation stated as a loop, and it is the only part of this note that could be
run mechanically tomorrow.

The measure row already has a finite shadow: `the-fold-lean.md` builds the `ℤ/n` host, its uniform
weight, and the doubling map. What that host does not add is independent trials.

The four are not the whole list. `the-fold-void.md` reads ten physical words and finds that they need six
hosts: these four, plus a **bundle** (for charge and field) and an **inertia** (for mass). A gauge theory
is not a measure, a flow, a bath, or an observer, so the four-stage programme is the first four nodes of a
six-node graph, not the graph.

## Stage 7: concept formation

The next capability is not a larger vocabulary. It is a system that can construct a task-scoped concept from varied instances, state which transformations preserve it, retain distinctions that another task may need, and revise the concept when a counterexample appears.

The formal proposal is in `agi/abstraction-and-concepts.md`. It uses quotient maps for task-relative equivalence, typed relations for concept structure, and commuting diagrams to test whether abstraction is consistent with representation changes. The Fold's existing orbit quotient is an exact small model; discovering useful equivalences from experience remains an engineering problem.

The stage is a proposed evaluation target, not evidence that the corpus or the architecture is AGI.

## Stage 8: executable concept learner

A first deterministic prototype now lives in `agi/concept_learner.py`, with tests in `agi/test_concept_learner.py`. It accepts scored candidate equivalences and explicit counterexamples, rebuilds task-specific partitions, and preserves the original instance payloads. It does not discover concepts autonomously; the evidence is supplied to it. This isolates the consistency and revision problem before adding a learned proposal mechanism.

## Stage 9: evidence-based proposal generation

`agi/concept_proposer.py` adds a deterministic proposal mechanism for the narrow task of physical-quantity equality. It normalizes supported metric units using exact rational arithmetic, proposes equivalence when dimension and canonical value agree, and emits hard negatives when canonical numerals agree but dimensions differ. The proposal batch can be inspected before it is applied to the Stage 8 learner. Tests are in `agi/test_concept_proposer.py`; the design and limits are in `agi/stage-9-proposal-generation.md`.

This is a real but narrow increase in autonomy: proposals are generated from structured observations rather than supplied manually. The unit table and task context remain explicit, so this is not open-domain semantic discovery or evidence of AGI.

## Failure modes

- **Rhyme inflation.** The measured fraction is flat: `0.692 ± 0.011` exact, `31%` rhyme or false
  friend, over nine readings (`the-fold-realization.md`). A system optimised on fluency will drift
  toward the `31%`, because that is where the language is easiest. The countermeasure is to score the
  exact column, which the gate already counts.
- **Gate overfitting.** `check.py` checks structure, not truth. A beautifully formed false theorem
  passes. The gate is necessary and not sufficient, and the ledger is what supplies the rest.
- **Dictionary, not engine.** The corpus maps; it does not generate. The generator is the model. The
  claim "this corpus is an AGI" is the false friend, and it is the one this note is most likely to
  encourage.

## The zones of this note

- the criterion, the type argument and the gate are exact: they are definitions and mechanical checks,
  and the corpus is a running instance;
- the stage table is a **projection** — a plan, not a derivation, and its dates are unstated on purpose;
- "this is a path to AGI" is a rhyme unless stage 1 closes, and stage 1 is the test of the rhyme;
- the four adjunctions are a reformulation of the existing programme, not a new claim.

The one sentence: an AGI is not a bigger corpus, it is a corpus that can say what it does not have —
and the gate that makes that sentence checkable already exists.


## Stage 10: compound-unit abstraction

`agi/concept_proposer.py` now parses products, quotients, and bounded integer powers of declared SI units into exact rational conversion factors and `(length, mass, time)` dimension vectors. It proposes equivalence only when both the normalized value and dimension vector agree, and produces hard negatives when equal numerals have incompatible dimensions. The Stage 10 note and expanded regression suite are in `agi/stage-10-compound-units.md` and `agi/test_concept_proposer.py`.

The existing GitHub Actions Python workflow now runs the concept learner and proposer tests on changes under `agi/`. This makes regressions observable in CI; it does not establish general semantic learning or AGI.

## Stage 11: typed quantities and affine units

The proposer now extends dimension vectors to `(length, mass, time, temperature)`, accepts optional semantic quantity kinds, and requires dimension, normalized value, and kind to agree before proposing equivalence. This prevents explicitly typed energy and torque from collapsing merely because they share dimensions. It also handles absolute Kelvin/Celsius/Fahrenheit using exact affine offsets, while treating temperature intervals as separate multiplicative units. Tests are in `agi/test_concept_proposer.py`; the design and limits are in `agi/stage-11-typed-affine-quantities.md`.

Kinds are supplied by the caller rather than learned. This remains a deterministic symbolic subsystem; it does not infer physical semantics or establish AGI.

## Stage 12: measurement intervals and calibration corrections

`agi/concept_proposer.py` now parses exact nominal quantities with optional closed measurement intervals and signed, caller-supplied calibration corrections. It normalizes nominal values and interval endpoints through the Stage 11 unit system, including affine temperature scales. The proposer keeps exact equivalence separate from interval compatibility: overlap is recorded as a separate relation and is never merged into the learner's equivalence classes. Disjoint intervals produce no compatibility proposal, not an automatic semantic counterexample.

The parser deliberately rejects unsupported statistical uncertainty types rather than assuming a probability distribution or coverage factor. It does not estimate calibration bias, propagate covariance, or infer measurement traceability. The implementation and limitations are documented in `agi/stage-12-measurement-uncertainty.md`; regression tests remain in `agi/test_concept_proposer.py`.

This stage adds explicit handling of measurement uncertainty to a narrow symbolic quantity task. It is not full metrology, statistical inference, autonomous scientific discovery, or evidence that AGI has been achieved.


## Stage 13: exact relational concept proposals

A separate module, `agi/relation_discovery.py`, now proposes exact proportional (`y = a*x`), inverse (`x*y = k`), and affine (`y = a*x + b`) relationships from paired scalar observations. Parameters use exact rational arithmetic. Each candidate is checked against every supplied observation; supporting keys and counterexamples are retained explicitly. Affine candidates require at least three observations so a two-point interpolation is not presented as evidence of discovery.

This module does not merge equivalence classes and does not claim causal laws. A relation that fits the finite observations is only supported on that dataset. Units, noisy regression, multivariate relationships, conservation laws, and experiment selection remain future work. See `agi/stage-13-relational-concept-discovery.md` and `agi/test_relation_discovery.py`.


## Stage 14: exact compositional relational concepts

A new agi/relation_composition.py embeds Stage 13's proportional, inverse, and affine hypotheses into exact fractional-linear maps (ax+b)/(cx+d). Composition uses exact rational matrix multiplication. The implementation canonicalizes projectively equivalent coefficient tuples, retains provenance, and separately tracks excluded inputs so algebraic cancellation cannot make an undefined intermediate step appear valid. Refuted source hypotheses cannot be composed.

Tests in agi/test_relation_composition.py cover affine-after-affine, proportional-after-affine, inverse poles and their pullbacks, exact fractions, constant maps, and rejection of refuted evidence. The CI workflow now runs this suite with the earlier concept tests.

This is algebraic composition of a small declared family, not autonomous discovery of arbitrary programs, causal inference, or evidence of AGI. A composed formula is not empirically validated merely because its component relations fit their supplied observations.


## Stage 15: independent validation of composed relations

The new agi/relation_validation.py evaluates fixed composed paths on separate validation observations. It reports endpoint matches separately from intermediate-step matches, records domain failures as refutations, rejects malformed or duplicate validation rows, and never refits relation parameters. Empty validation sets are marked insufficient rather than passed. Tests cover held-out affine chains, hidden intermediate errors despite a matching endpoint, endpoint counterexamples, domain failures, and exact-input restrictions. This is finite held-out testing, not a universal proof or a guarantee of distributional generalization.


## Stage 16: evidence-based comparison of competing relational models

The new agi/relation_selection.py compares caller-supplied composed paths on the same held-out observations. It reports endpoint and intermediate errors separately, counts domain failures, and applies a transparent structural-complexity proxy only after empirical mismatch counts. Exact projectively equivalent composed maps with identical excluded-input sets are grouped without deleting alternative derivations. Empty validation data produces no winner. The ranking is deterministic, not probabilistic, and remains limited to the declared scalar fractional-linear family; caller-managed separation of validation data remains essential.


## Stage 17: controlled discovery, selection, and final testing

`agi/three_way_evaluation.py` adds a disjoint three-part protocol. Candidates are declared as originating from discovery rows, compared on validation rows, and only the selected candidate is evaluated on the untouched test partition. Overlapping partition keys, invalid provenance, duplicate candidate IDs, and missing partitions are handled explicitly. Provenance declarations improve auditability but cannot prove that external candidate construction did not leak held-out information. This is a finite-sample evaluation protocol, not a guarantee of generalization.


**AGI concept-learning prototype (Stage 18):** Stage 18 adds finite active experiment design for competing composed relations. It ranks caller-supplied exact rational inputs by pairwise prediction separation, reports candidate coverage, and treats undefined predictions as missing coverage rather than agreement. The score is a scale-dependent heuristic; no real-world experiment is executed or presumed safe. See `agi/active_experiment.py` and `agi/stage-18-active-experiment-design.md`. This is a narrow active-learning component, not autonomous science or AGI.


## Stage 19: append-only evidence feedback and hypothesis revision

`agi/evidence_revision.py` adds an immutable evidence ledger. Each newly observed exact input/output pair is checked against every supplied candidate; matches are retained, mismatches and domain failures are recorded as refutations, and earlier predictions remain unchanged. The accumulated observations are then passed to the existing exact relational proposer. Newly supported proportional, inverse, or affine hypotheses are returned as unselected candidates, not installed automatically. This is a narrow scalar feedback loop; it does not infer noise, causality, arbitrary programs, or AGI.


## Stage 20: reusable concepts across representations

`agi/representation_transfer.py` adds exact transfer for scalar affine relations under caller-declared invertible affine coordinate maps. It analytically transforms coefficients rather than refitting target examples and verifies that residual zero/nonzero status is preserved. The supported family is deliberately narrow; no general semantic transfer or AGI claim follows. See `agi/stage-20-representation-transfer.md`.


## Stage 21: compositional abstraction

`agi/compositional_abstraction.py` represents an affine concept as an immutable ordered path, retains intermediate structure while deriving its endpoint map, distinguishes structural equivalence from endpoint-only equivalence, and transfers every edge through a separate invertible coordinate map for each layer. Each commuting square is checked exactly on supplied inputs. See `agi/stage-21-compositional-abstraction.md`.


## Stage 22: exact invariant discovery

`agi/invariant_discovery.py` extracts the multiplier, identity/nonzero-translation class, and fixed-point structure of scalar affine self-maps. It derives conjugates under invertible affine coordinate changes and verifies exact preservation of the multiplier and covariance of fixed points. The scope is deliberately limited to rational affine maps. See `agi/stage-22-invariant-discovery.md`.
